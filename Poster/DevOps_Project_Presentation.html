PROJECT MOTIVATION

Problem Statement & Project Objectives

⚠️ The Security Operations Problem
  • Alert Fatigue: SOC analysts are overwhelmed by millions of raw, heterogeneous log lines with zero triage.
  • Delayed Incident Response: High-severity intrusion events go unnoticed due to slow manual log parsing.
  • Configuration Drift: Manual server setups cause environment discrepancies and frequent deployment downtime.
  • Missing Quality Gates: Vulnerable and breaking code frequently escapes into production without automated tests.
🎯 Core Engineering Objectives
  • Automated Log Ingestion: Real-time regex parsing, classification, and severity tagging (CRITICAL, WARN, INFO).
  • Continuous Quality Gates: Jenkins CI pipeline executing 15 JUnit and headless Selenium tests prior to packaging.
  • Production-Hardened Container: Multi-stage build on Alpine Linux running under non-root account (appuser:1001).
  • Idempotent Orchestration: Complete Ansible playbook automation with verified changed=0 and 15s rollback.

QUALITY ASSURANCE

CI/CD Pipeline & Continuous Testing Quality Gate

🔄 Jenkins Pipeline Workflow
  • Declarative Jenkinsfile: Automated stages for Checkout, Build, Unit Test, UI Test, Package, and Deploy.
  • Webhook Triggers: Immediate validation triggered on every Git commit and pull request.
  • Artifact Archiving: Proven, reproducible Spring Boot JAR artifacts automatically tagged and archived.
  • Automated Quality Gate: Pipeline automatically fails and aborts build if any test or assertion fails.
🧪 Comprehensive Test Verification
  • 15 JUnit Unit Tests: Validates log parsing, regex extraction, alert severity thresholds, and search filters.
  • Selenium UI Automation: Headless Chrome tests simulating user login, log review dashboard, and query filters.
  • Defect Injection Validation: Injected faulty assertions to prove that pipeline blocks bad builds before production.
  • Audit Reports: Jenkins publishes Surefire XML reports and browser snapshots for test traceability.

CONTAINER SECURITY

Docker Hardening & Cloud-Ready Packaging

📦 Container Optimization
  • Multi-Stage Build: Maven compile environment is separated from runtime; final image is only 166 MB.
  • Alpine Linux 3.19: Minimal operating system footprint drastically cuts potential vulnerability surface.
  • Docker Layer Caching: Dependencies copied before source files for rapid, incremental build iterations.
  • Isolated Bridge Network: Only port 8080 exposed with strict container communication boundaries.
🛡️ Security Hardening Standards
  • Non-Root User: Runs strictly under service account appuser:1001 to prevent root escape risks.
  • Filesystem Protection: Core runtime filesystem locked down against unauthorized modifications.
  • Built-in Health Checks: Probes GET /actuator/health every 15s to detect and restart hung services.
  • Graceful Shutdown: Handles SIGTERM cleanly to complete active log reviews before termination.

INFRASTRUCTURE AS CODE

Ansible Provisioning, Idempotency & Rollback

📜 Declarative Configuration
  • Modular Roles: Clean separation for prerequisite packages, Docker engine, security rules, and app deploy.
  • Jinja2 Templating: Dynamic configuration of environment files, systemd services, and log settings.
  • Verified Idempotency: Consecutive playbook execution produces changed=0, failed=0.
  • Environment Parity: Identical declarative playbooks used across staging and production environments.
⚡ Rapid Disaster Recovery
  • Sub-15s Rollback (RTO < 15s): Automated rollback playbook restores previous stable artifact within 15 seconds.
  • Zero-Touch Operations: Re-linking and service restart executed entirely through Ansible automation.
  • Key Viva Takeaway 1: End-to-end continuous delivery pipeline from Git commit to verified container execution.
  • Key Viva Takeaway 2: Guaranteed infrastructure stability with zero configuration drift.
